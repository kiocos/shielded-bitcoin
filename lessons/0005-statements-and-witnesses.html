A claim and the evidence for it.

Start here: what does someone claim, what makes it true, and what does the other person get to see?

A statement is a precise claim. A witness is data that makes the claim checkable. The checking rule says which witnesses count.

An actual small computation

Can some of these numbers add up to 31?

Choose numbers. Each can be used at most once.

No numbers selected · sum = 0

Try finding a selection before asking for a solution.

Public information

The list and target: 3, 6, 11, 15, 22, 29 and 31.

The claim: “A selection from this list totals 31.”

A witness

The selected entries 3, 6, 22.

The check: all are allowed entries, none is reused, and 3 + 6 + 22 = 31.

Once you have that witness, you can check it directly. You do not need to search through other selections. A witness need not be secret; this one is visible.

Translate the notation used in papers

x means the public information. w means the witness. R(x, w) means the checking rule applied to both. Researchers call this rule a relation.

There exists w such that R(x, w) = 1

Read it as: “There is some evidence that passes the check for these public inputs.” The 1 means “passes.” A language is the collection of public inputs for which such evidence exists.

For an NP statement, the witness has a bounded size and the check runs efficiently as input size grows. We will unpack those conditions next.

Definition: Stephen Cook, checking relations and NP, p. 2. The number exercise is an original teaching example.

Now make the claim about a payment

In Shielded Bitcoin, a wallet claims: “I know input notes in this tree, I can spend them, and this transfer follows the rules.” Its witness includes private notes, spending secrets and paths showing where the inputs occur in the tree.

The wallet uses that witness to produce a separate object: a proof. Replaying indexers receive the proof and public transfer data. They do not receive those private inputs. The next lessons explain how this is possible.
