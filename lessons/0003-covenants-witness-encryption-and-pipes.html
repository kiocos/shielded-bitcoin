What does a PIPE actually unlock?

Your goal: explain witness encryption, then distinguish key release from a covenant.

Start with the condition

A covenant constrains how a coin may be spent—for example, by restricting the next transaction’s outputs. PIPEs v2 instead provides conditional release of a signing key. Once recovered, that key can sign arbitrary transactions; the paper explicitly disclaims persistent, per-signature covenant enforcement. §1.1

What “witness encryption” means

A statement defines a checkable condition. A witness is data satisfying it. WE encrypts a message under the statement; a valid witness enables decryption. PIPEs needs an extractable-security assumption: learning the protected message requires knowledge of a witness. §2.5

An actual condition · a toy demonstration

“Know two integers greater than 1 whose product is 77.”

Try 3, 11, then 7, 11. The pair is a witness. The number 77 alone is not.

The demo signing key has not been released.

This only illustrates the witness relation. It is not encryption, a secure factoring example, or a PIPE implementation. Real WE must protect the message even if an attacker rewrites the decryption software.

PIPE setup also includes a ZK proof that the encrypted secret matches the public signing key. The authors propose MPC setup to avoid revealing that secret to any participant. §4

Key-release limit: suppose an unlocking proof describes a payment to Bob. Learning the ordinary key does not itself force the holder’s later Bitcoin transaction to pay Bob. Do not describe this mechanism as a complete, transaction-bound peg.
