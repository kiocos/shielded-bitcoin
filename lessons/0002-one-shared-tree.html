Your goal: predict what changes in shielded state when a Bitcoin block is replayed.

Within one deployment, every accepted output contributes a leaf to one global note tree. Indexers reconstruct their own copies of the same state. Notes are not partitioned by indexer, owner or transfer.

A tree root proves existence, not current spendability. A proof may use an eligible older root, but replay compares nullifiers with the current accepted set. Going back to an old root does not let you spend twice. §8

How can an indexer add leaves without decrypting notes?

A leaf hashes public output fields together with transfer-binding data and the output index. The proof checks the ciphertext relation to the hidden output note. Everyone can derive the same leaf; they do not need its plaintext. §9

Wallets scan for notes they can decrypt. A wallet’s list of its own notes is bookkeeping, not a separate global protocol tree.

Do indexers vote? What about reorganizations?

They independently apply deterministic rules. A wallet trusting an unverified indexer can be misled about state. A Bitcoin reorganization changes the history being replayed, so affected tree state and roots must be recomputed. Append-only describes growth along a fixed chain history. §15

Recall: a tree has 10 leaves. An accepted transfer spends 2 notes and creates 2 outputs. How many leaves now?
